Gala source files use the `.gala` extension. The compiler accepts top-level function definitions;
the parser also has AST forms for structs, enums, traits, implementations, type aliases, constants,
and imports.

## A classical first program

Create `hello.gala`:

```gala
fn main() -> Int pure {
    return 42;
}
```

Check it through the CLI:

```bash
cargo run --bin gala -- build hello.gala
```

The current `build` command performs the frontend compilation and prints the source or a labeled
placeholder for a requested emission. It does not yet produce a native executable.

## A quantum-shaped program

The language model uses ownership-threaded values. A Bell-pair-shaped function can be written as:

```gala
fn bell(a: Qubit, b: Qubit) -> (Qubit, Qubit) quantum {
    let a = h(a);
    let (a, b) = cx(a, b);
    return (a, b);
}
```

The return value makes the ownership story explicit: the two qubits are still live and are returned
to the caller. In the current implementation, built-in names and quantum operations are represented
in the HIR and type-checking layers, but the execution backends are not complete.

## See the linear rule

This program attempts to use a moved qubit twice:

```gala
fn invalid(q: Qubit) -> (Qubit, Qubit) quantum {
    let first = q;
    let second = q;
    return (first, second);
}
```

The intended rule is that a linear quantum value cannot be duplicated. The repository contains
conformance fixtures for duplicate use, use after consumption, aliasing, and implicit drop under
`tests/conformance/linearity/`.
