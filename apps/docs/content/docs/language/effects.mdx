---
title: Effects
description: The pure, quantum, and probabilistic worlds of Gala.
---

Effects describe what a function is allowed to do. They are part of Gala’s design contract and are
represented in the AST and type checker.

## The effect lattice

```text
pure  ⊑  quantum  ⊑  prob
```

- `pure`: deterministic classical computation.
- `quantum`: quantum evolution without measurement.
- `prob`: computation that has crossed the measurement boundary and may be stochastic.

The ordering describes which lower-level operations a context may call. A `quantum` function can
use pure operations, while a pure function cannot perform quantum operations. A quantum function
cannot call a probabilistic operation such as measurement.

```gala
fn classical(value: Int) -> Int pure {
    return value + 1;
}

fn rotate(q: Qubit) -> Qubit quantum {
    return h(q);
}

fn sample(q: Qubit) -> Measured<Bool> prob {
    return measure(q);
}
```

## The measurement boundary

`measure` is destructive for the qubit and produces a classical result. A function that performs
measurement must be `prob` in the design model. This keeps reversible quantum kernels visibly
separate from stochastic orchestration.

## Diagnostics

Effect diagnostics are in the `E03xx` family. The registry includes effect mismatch,
pure-calls-quantum, quantum-calls-prob, measurement-in-quantum, and effect-polymorphism errors.
The current type checker reports explicit effect boundary violations; broader inference and
higher-order effect polymorphism remain active design work.

## Why effects matter

Effects are useful beyond documentation. They provide a boundary for:

- deciding whether an adjoint is meaningful;
- selecting a backend profile for adaptive measurement;
- explaining why a supposedly reversible function cannot be reversed;
- separating deterministic classical preprocessing from probabilistic results.
