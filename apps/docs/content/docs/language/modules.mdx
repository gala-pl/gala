The language model uses dotted module paths and imports:

```gala
import gala.core.*
import gala.gates.{ h, cx }
import mypkg.encoding as encoding
```

The AST and HIR include import nodes, module identifiers, definitions, and a module-graph builder.
The package crate provides the manifest and lockfile data structures.

## Project layout

```text
my-project/
├── gala.toml
├── gala.lock
├── src/
│   ├── main.gala
│   └── helpers.gala
└── tests/
```

## Manifest

`gala-pkg` reads a TOML manifest with a `[package]` table and optional `[dependencies]` and
`[dev-dependencies]` tables:

```toml
[package]
name = "my-project"
version = "0.1.0"
edition = "2021"
license = "Apache-2.0"

[dependencies]
gala-std = "0.1.0"
```

The current resolver can serialize simple, git, and path dependencies into a lockfile-shaped
structure. Registry fetching and a complete dependency graph resolver are still planned.

## Standard library source

The repository’s Gala-source library lives under `library/std`. The Rust `gala-std` crate currently
provides classical helper modules; the Gala-source files are the intended home for core, gates,
algorithms, VQA, noise, and hardware layers as they mature.
