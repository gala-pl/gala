---
title: Control flow
description: Blocks, conditionals, matches, loops, and expression-oriented control flow.
---

Gala’s AST and parser model control flow as expressions where practical. Blocks contain statements
and may finish with a trailing expression; `if`, `match`, `for`, and `while` forms are represented
as distinct expression nodes.

## Blocks and returns

```gala
fn absolute(value: Int) -> Int pure {
    if value < 0 {
        return -value;
    } else {
        return value;
    }
}
```

`return` is an explicit statement in the current parser. A block can also have a tail expression,
which is useful for the ownership-threading style used by quantum functions.

## Branches and patterns

```gala
fn classify(value: Int) -> Bool pure {
    match value {
        0 => true,
        _ => false,
    }
}
```

The AST includes identifier, wildcard, tuple, struct, and literal patterns. Match exhaustiveness
and rich pattern diagnostics are not yet a complete compiler feature.

## Loops

The surface model includes range-based `for` and `while` expressions:

```gala
fn sum(limit: Int) -> Int pure {
    let mut total = 0;
    for value in 0..limit {
        total = total + value;
    }
    return total;
}
```

Quantum loops must still respect linear ownership on every path. A qubit cannot be consumed on one
branch and reused on another without a type-safe ownership story; this is an important area for
future control-flow conformance coverage.
