Testing is split between implementation tests and source-level conformance fixtures.

## Workspace gates

```bash
cargo fmt --check
cargo build --workspace
cargo test --workspace
cargo clippy --workspace -- -D warnings
```

The docs app has its own checks under `apps/docs`:

```bash
nub run test
nub run format:check
nub run lint:check
nub run build
```

## Conformance layout

```text
tests/conformance/
├── types/
├── effects/
├── linearity/
├── uncompute/
├── diff/
├── qir/
├── run/
├── valid/
└── errors/
```

Fixtures are source files with comments describing expected behavior. They cover type recognition,
effect boundaries, duplicate and consumed qubits, auto-uncomputation refusal cases, and parser
errors. The conformance harness is the best place to pin a language rule that should not regress.

## Property, snapshot, and fuzz tests

The workspace includes property tests for lexing, parsing, type helpers, formatting, and driver
behavior, along with snapshot tests and fuzzing infrastructure. The future quantum-aware suite is
intended to check unitarity, reversibility, clean ancillas, gradients, and effect honesty once the
simulation and lowering backends are implemented.

## What a new feature needs

For a language or compiler behavior change, add focused tests for the success path and any refusal
path, update diagnostic explanations, and update the relevant docs page. Do not make a test pass by
weakening an invariant.
