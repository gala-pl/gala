Run the CLI from the repository with:

```bash
cargo run --bin gala -- <command> ...
```

## Commands

| Command | Current interface |
| --- | --- |
| `gala run <file> [--shots N]` | Read and compile a file; current output is a simulated run placeholder. |
| `gala build <file> [--emit KIND] [--output PATH]` | Compile and emit source or a labeled representation. |
| `gala test [--file FILE]` | Check an optional file and print the current simulated test result. |
| `gala fmt <file> [--check]` | Print canonical formatting, or fail if the file differs. |
| `gala new <name> [--lib]` | Create `gala.toml` and `src/main.gala` or `src/lib.gala`. |
| `gala repl` | Read lines and check them; currently echoes valid input. |
| `gala add <pkg> [--version V] [--git URL] [--path PATH]` | Update the current manifest. |
| `gala explain <code>` | Print a short explanation for known codes. |
| `gala lsp` | Start the current LSP entry point, which is a stub. |

## Build emission

The current CLI accepts `gir`, `qir`, and `llvm` as `--emit` values:

```bash
cargo run --bin gala -- build examples/hello_world.gala --emit gir
cargo run --bin gala -- build examples/hello_world.gala --emit qir --output build/out.ll
```

These paths are intentionally documented as current behavior, not as completed backend support.
The CLI adds a label and writes the source to the requested output; use the backend pages for the
actual emitter status.

## Formatting

```bash
cargo run --bin gala -- fmt examples/hello_world.gala
cargo run --bin gala -- fmt examples/hello_world.gala --check
```

Without `--check`, the command prints formatted source to stdout. It does not currently overwrite
the input file or recursively walk a directory.

## Project scaffolding

```bash
cargo run --bin gala -- new demo
cd demo
cargo run --manifest-path ../Cargo.toml --bin gala -- build src/main.gala
```

The scaffold includes a manifest with a `gala-std` dependency and a minimal source file. Dependency
resolution and registry installation are not yet complete.
