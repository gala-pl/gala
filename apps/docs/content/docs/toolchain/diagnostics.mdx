---
title: Diagnostics
description: Error values, code families, and the current explanation surface.
---

Gala represents compiler findings as values in `gala-diagnostics`. A diagnostic has a code,
severity, message, labeled spans, notes, and optional help text. A `Diagnostics` collection can
contain multiple findings and reports whether any are errors.

## Code families

| Family | Examples | Meaning |
| --- | --- | --- |
| `E01xx` | `E0101`, `E0102` | Syntax, token, and source errors |
| `E02xx` | `E0201`, `E0206` | Type and `Qubits<N>` size errors |
| `E03xx` | `E0301`, `E0304` | Effect boundary errors |
| `E04xx` | `E0401`, `E0404` | Linear ownership and aliasing errors |
| `E05xx` | `E0501`, `E0502` | Uncomputation failures |
| `E06xx` | `E0601`, `E0602` | Backend capability and emission errors |

The complete registry is in `crates/gala-diagnostics/src/lib.rs`. The source files under
`crates/gala-diagnostics/src/explain/` hold longer explanations for selected codes.

## CLI explanations

The current CLI has seeded short explanations for `E0101`, `E0201`, `E0301`, `E0401`, and `E0501`:

```bash
cargo run --bin gala -- explain E0401
```

Unknown codes return a generic message. The roadmap calls for markdown/JSON explanations and
suggested fixes, but those interfaces are not shipped yet.

## Diagnostic philosophy

Quantum-specific errors should describe both the programming rule and the physical reason. For
example, a use-after-consume error should identify the operation that consumed the qubit and direct
the author toward the classical measurement result or a correctly threaded return value.

## Current rendering

The emitter currently prints code, message, labels, notes, and help to stderr. Its API is ready
for richer `ariadne` rendering, but the present implementation is deliberately lightweight.
