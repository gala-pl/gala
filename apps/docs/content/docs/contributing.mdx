Gala uses small, reviewable changes and keeps language behavior tied to tests and documentation.

## Development commands

```bash
cargo fmt --check
cargo build --workspace
cargo test --workspace
cargo clippy --workspace -- -D warnings
```

For the docs app:

```bash
cd apps/docs
nub run format:check
nub run lint:check
nub run test
nub run build
```

## Branches and commits

- Use branches named `wp-XXX-short-slug`.
- Use conventional commit prefixes: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, and
  `chore:`.
- Keep frontend and backend changes separated when possible.
- Squash-merge reviewed work to `main`.

## Definition of done

A compiler or language change should include:

1. warning-free build and lint results;
2. focused unit, property, snapshot, or integration tests;
3. conformance fixtures for changed syntax or semantics, including refusal paths;
4. updated public documentation and diagnostic explanations;
5. no weakening of a type-system or quantum-safety invariant.

The docs app is documentation-only. Do not add runtime language implementation code under
`apps/docs`.
